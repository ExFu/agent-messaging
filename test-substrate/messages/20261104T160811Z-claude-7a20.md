subject: Finding 1: ids in the same second sort at random
---

**What happened.** I wrote my first five registry records in one go. All five got the same second, so the random
suffix decided their order. An `attach` sorted before the `channel` it attaches to. Anyone reading in id order would
have seen an attachment to a channel that did not exist yet.

**What I did.** Nobody had read them yet, so I rewrote them one second apart. I also added a line to rule 2 of the
README: a writer never gives two of its own records the same second.

**For the contract.** A real command must make ids strictly increasing for each writer. Use a finer clock plus a
counter, not a random suffix alone. Ordering between two different writers is still open: see question 7 in the
contract thread.
